# DiagAuthor 0.1.0 검토·수정 기록 (2026-09-25)

## 1차: 원인
- CDD 파싱·가져오기 백엔드는 설치 예제 2개(ABS_ESP, Multilingual)에서 동작함.
- 실제로 막힌 곳: Windows 저장 실패(`Session.save`의 읽기 전용 핸들 `os.fsync` → OSError, 앱 로그로 확인), CDD 진입점이 메뉴에만 있음, 속성 창이 DID 구조를 표시하지 않음, 가져오기 직후 Ctrl+Z 시 빈 프로젝트.
- 추가 발견: CDD `COMP div`를 무시해 물리값이 틀리게 가져와짐(Voltage 1/16 → 1). `s`/`e` 범위, `EXCL`, ECU 사용자 속성(CAN ID)도 조용히 버려짐.
- 빌드: Windows PowerShell 5.1에서 `$ErrorActionPreference='Stop'` + native stderr 리디렉션 때문에 PyInstaller 첫 INFO 줄에서 build.ps1이 중단됨.
- 1차 수정은 Windows에서 확인 완료(테스트 15개, 재빌드, GUI 스모크).

## 2차: CDD 서비스·상태·DTC, 스키마 2 (Windows 확인 완료)
- Windows: 테스트 29개 통과, 재빌드 성공, GUI 스모크 통과(미리보기 "서비스 35 · DTC 31 · 상태 5", DID 18, 0x010B 속성, 저장). 타입 편집 창 예외값 탭은 자동 확인 범위 밖.
- 서비스: DIAGINST → DCLTMPL(SHSTATIC·SHPROXY) → DCLSRVTMPL → PROTOCOLSERVICE를 바이트 단위로 해석, 고정 프로파일(0x10/0x11/0x22/0x2E/0x31/0x3E)과 같을 때만 가져옴. ABS: 서비스 59 중 35, DTC 31, 상태 5, DID 18.
- 상태: mayBeExec/trans = 문서 순서 전역 상태 번호. 세션 상태 코드는 0x10 subfunction에서 도출. 상태가 안 적힌 그룹은 제한 없음(추론, 도움말 확인 필요). 초기 상태 = 첫 상태.
- DTC: faultMemory RECORDDATAOBJ RECORD v=코드, TEXT=이름, 레코드 항목 → object_attributes.
- 스키마 2: data_types.raw_lower/raw_upper, raw_exclusions. migrations.py가 v1 → v2 변환(작업 사본, 저장 시 .bak).
- ODX(예제 ODXEnvelope 근거): 범위 밖·EXCL undef·텍스트 표 미대응 원시값 → SCALE-CONSTR NOT-DEFINED, DTC-DOP 자식 순서 Vector와 동일, DISPLAY-TROUBLE-CODE 0x%08X, 레코드 항목 → SDGS. noSignal/invalidSignal은 근거 없어 출력 차단.

## 결정 근거 (Vector ODX 출력 대조)
- LINCOMP: phys = raw·(f/div) + o (0107 Voltage 0.0625, 010B Acceleration 0.1/-13). 비유한 소수 계수는 미지원 보존.
- 0112 Time_2_Byte e=730 → NOT-DEFINED 731..65535(라벨 없음), 0100 Percent EXCL undef → NOT-DEFINED + 빈 SHORT-LABEL, TEXTTABLE 미대응 → NOT-DEFINED.

## 자동화 메모
- 작업 지침은 저장소 CLAUDE.md: 구현·빌드·테스트는 Opus 5.5 low, 검토·난제는 Opus 5.5 high.
- Windows 확인은 콘솔에 진행이 보이는 스크립트로: build\run_tests.cmd(테스트), build\run_checks.cmd(테스트→빌드→GUI), build\run_gui_smoke.cmd(GUI). 결과 build\checks\. 원격에서는 파일 탐색기 더블클릭으로만 실행 가능(터미널은 클릭 전용 권한이라 입력 불가).
- Qt UIA Invoke는 동기 실행이라 모달 창을 여는 버튼에는 쓰지 말 것(교착).
- 테스트의 sqlite 연결은 contextlib.closing으로 닫기(`with sqlite3.connect`는 닫지 않아 Windows에서 파일 교체 거부).

## 3차: 원문 배치 서비스, 예외값 ODX, 스키마 3 (Windows 확인 완료: 테스트 34, 빌드, GUI "서비스 48 · DTC 31 · 상태 5")
- 근거: CANdelaStudio 도움말 CHM을 build\extract_help.cmd(7-Zip)로 build\reference\에 풀어 대조(저장소 제외), Import/UDS-ExampleEcu.pdx 대조.
- 상태: 빈 그룹 = 제한 없음은 도움말 병렬 그룹 규칙 + [STTR-R200](그룹 전체 차단은 출력 거부)로 확정. 초기 상태 = 첫 상태(도움말 정의).
- 예외값: 도움말 110_ODXExport Table 40 — undef→NOT-DEFINED, noSignal/notImplemented/unexpectedResult→NOT-AVAILABLE, invalidSignal→NOT-VALID. PDX Frequency_Counter로 noSignal 확인.
- raw 서비스: 고정 프로파일과 다른 서비스(0x27, 0x85, 0x2F, DID 참조 없는 0x22)를 바이트 배치 그대로 읽기 전용으로. 서비스 35 → 48.
- 스키마 3: services.profile, role other, 예외 종류 확장. CHECK 변경은 foreign_keys=OFF로 테이블 재생성.
- 도움말상 Vector 상태 모델 출력: 그룹→STATE-CHART, 상태→STATE, 전이→STATE-TRANSITION, START-STATE=초기 상태. precondition 대응은 설명 없음.
- ODXStudio 7 설치됨: 독립 XSD는 없고(DLL 내장) EffectiveODXChecker로 외부 검사 가능.
